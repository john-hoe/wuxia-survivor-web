# 34 Post-MVP Route

## 目的

本文记录 `survivor-web` 在 MVP 验收通过后的推进顺序。

用户已确认：朋友试玩收集真实反馈放到最后。MVP 通过后先做一轮可控的内部扩展和打磨，再交给朋友体验，避免真实反馈被明显未完成项污染。

## 第一性原则

- 先冻结可工作的基线，再改数值和内容。
- 先把已有 1 个关卡调准，再增加第二关。
- 先解决高频体验问题，再扩大美术和玩法规模。
- 朋友试玩样本少，应留给接近完整的版本。
- 所有 post-MVP 任务仍遵守“做完 -> 检查 -> 多模型 review -> 验证 -> 修复 -> 再验收 -> 更新 dashboard”。

## 总路线

```text
MVP 冻结
-> 数值平衡
-> 正式音频
-> 移动端适配
-> 青石山道小扩展
-> 第二关
-> 最终朋友试玩
```

## 路线拆分

| 顺序 | ID | 阶段 | 目标 | 不做什么 | 完成标准 |
| ---: | --- | --- | --- | --- | --- |
| 1 | SW-POST-001 | MVP 冻结 | 固化当前已成功 MVP 为可回退基线 | 不加新玩法、不调大数值 | `35-mvp-freeze-baseline.md` 存在；typecheck/build/QA 基线可复跑；证据和 dashboard 对齐；调试入口边界清楚 |
| 2 | SW-BAL-001 | 数值平衡 | 调准 6 到 8 分钟一局的压力、成长和死亡/胜利概率 | 不加第二关、不做新敌人大批量扩展 | 第一次领悟 15-25 秒；首次明显压力 60-120 秒；普通失败 3-5 分钟；头目 360 秒；胜利 6-8 分钟 |
| 3 | SW-AUDIO-002 | 正式音频 | 把本地占位音效升级为正式 BGM/关键 SFX | 不接实时在线音频生成、不把 API key 放前端 | 音效不刺耳、不糊、不抢 UI；静音/音量/节流仍通过；仓库无 key 泄漏 |
| 4 | SW-MOBILE-001 | 移动端适配 | 改善移动端横屏、触控、全屏、HUD 避让和性能 | 不做竖屏完整玩法 | 主流移动横屏可玩；虚拟摇杆不遮挡；HUD 不压核心区域；移动端目标 FPS 45-60 |
| 5 | SW-CONTENT-001 | 青石山道小扩展 | 在首关内增加少量内容验证扩展方式 | 不直接做大地图、不同时塞多个新系统 | 新增 1 个小敌人/精英或 1 个小机制；不破坏原 6-8 分钟节奏 |
| 6 | SW-STAGE-002 | 第二关 | 在首关稳定后做第二关规格和首版实现 | 不复用成换皮关卡、不急着做多关卡系统 | 第二关有不同视觉/波次/头目或机制差异；能独立进入、完成和结算 |
| 7 | SW-QA-002 | 最终朋友试玩 | 收集真实玩家反馈，判断是否值得继续扩展 | 不让半成品问题污染反馈 | 至少 5 次试玩记录；70% 愿意再开；70% 理解死因；60% 能说出构筑差异 |

## 数值平衡目标

| 指标 | 目标范围 | 说明 |
| --- | ---: | --- |
| 第一次领悟 | 15-25 秒 | 太早会没有期待，太晚会无聊 |
| 前 3 分钟领悟次数 | 4-8 次 | 保证构筑开始成型 |
| 首次明显危险 | 60-120 秒 | 不能 20 秒就压死，也不能 3 分钟无压力 |
| 普通失败窗口 | 3-5 分钟 | 对新玩家有压力但不立刻劝退 |
| 头目出现 | 360 秒 | 保持 MVP 已验收节奏 |
| 胜利完成 | 6-8 分钟 | 一局要短，但要有完整闭环 |
| 稳定构筑数量 | >= 2 种 | 至少能玩出不同套路，而不是唯一正确答案 |

## 正式音频目标

| 类型 | 优先级 | 验收 |
| --- | --- | --- |
| BGM loop | P0 | 60-120 秒可循环；不压过命中/受伤/领悟提示 |
| 命中/击杀/拾取 | P0 | 高频播放不刺耳；节流后仍有反馈 |
| 领悟/进阶/头目预警 | P0 | 事件语义清晰，3 秒内能听出重要程度 |
| 菜单/按钮/结算 | P1 | 风格统一，不像商城促销音 |
| 阵亡/胜利 | P1 | 情绪明确但不过长 |

## 移动端目标

| 项 | 目标 |
| --- | --- |
| 方向 | 横屏优先 |
| FPS | 45-60 |
| 输入 | 虚拟摇杆不遮挡少侠、敌人和底部招式槽 |
| HUD | 顶部信息不压住怪潮关键区域 |
| 安全区 | 适配刘海、圆角和浏览器地址栏变化 |
| 竖屏 | 仍只做旋转提示，不做完整竖屏玩法 |

## 第二关前置条件

必须满足以下条件才进入 `SW-STAGE-002`：

- `SW-BAL-001` 数值平衡通过。
- `SW-AUDIO-002` 正式音频不会干扰战斗读局。
- `SW-MOBILE-001` 移动横屏可玩。
- `SW-CONTENT-001` 证明“增加小内容不会破坏首关节奏”。
- 现有首关仍能通过 `npm run typecheck`、`npm run build` 和浏览器 QA。

## LLM 决策

本路线暂不把 LLM 集成进核心战斗。

原因：

- survivor-like 核心是低延迟、确定性、数值和帧稳定。
- LLM 更适合复盘、战绩说书、构筑建议和反馈整理。
- 如果以后接入 LLM，应单独开 `SW-LLM-001`，从战后复盘开始，不进入伤害、掉落、抽秘籍概率、Boss 行为或怪潮判定。
